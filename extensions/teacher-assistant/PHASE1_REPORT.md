# Phase 1 执行记录

Phase 1 已实现教师专业版基础。完整产品的 Phase 2–9 继续保留于实施清单。

## 实际交付

原生 `teacher-pro` Profile 已创建于 `E:\TeacherAgentData\dev-home\profiles\teacher-pro`。教师 Plugin 通过目录联接安装，Agent 端已启用。对该真实 Profile 的 `teacher_records course.list` 调用返回空列表，并初始化独立教学数据库。

源码集中于 `extensions/teacher-assistant`。注册入口使用公开的 PluginContext API，提供 `teacher_records`、`teacher_tasks`、原生 Skill、冻结的教师系统提示段和命名空间 RPC。Desktop 半部通过统一插件机制加载，使用公开 SDK。

教学数据库位于 Profile 的 `plugin-data/teacher-assistant/teaching.db`。模式版本为1，包含课程、班级、学生、课程班级、选课、Workflow、步骤、审批、幂等回执和审计表。每次写入采用事务，请求重复使用回执，记录更新使用版本校验。

课程时间分别保存教学小节分钟、小节数和休息合计分钟。默认计算得到教学80分钟与日历90分钟。单小节课程要求休息为0。

学生学号具有唯一约束，选课前验证课程和学生均有效、学生班级已关联课程。调整学生班级时校验已有课程关系。归档保留数据及其审计历史。

课程设置 Workflow 支持待执行、执行中、待审核、完成、失败和取消。执行步骤、课程写入与审批创建在同一事务内提交。步骤中途失败使用保存点回滚，失败任务可重试。教师审核检查任务与课程版本，Agent 工具无法提交审核操作。

## Desktop 与权限

中文工作台包含课程、班级、学生档案、课程身份关联、任务与审批、模型与权限六项可操作入口。数据由真实 Gateway RPC 读取和写入，空数据库显示空状态。

首次通过原生“技能与工具 → 插件”开关启用 Desktop 半部，符合统一插件的原生启用机制。安装脚本保留此入口并显示操作提示。

学生记录默认只经本地教师界面读取，Agent 访问需要教师在配置页授权。Agent 禁用操作也会约束 Workflow 中的课程创建。模型配置只保存服务商与模型名称，凭据沿用 Hermes 原生设置。权限设置使用严格类型验证，并作为一个配置对象原子保存。

审批 RPC 依赖原生 Gateway 的操作者 `session:control` 权限。该业务权限约束教师工具及 RPC，Hermes 原生终端继续使用本机操作者权限。
