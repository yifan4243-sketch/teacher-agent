# Phase 4 图片执行与检查模块

本检查点继续已批准的 V5.1 开发。Phase 4 仍需完成可选参考素材管理及真实模型视觉质量验证，Phase 5–9 保留全部范围。

## 实现

- 已审核蓝图自动提供教材、授课稿、教案、教学目标、页面用途和主题提示词，无需人工固定样式图。
- 使用 Hermes 公开 `tools.registry` 分发原生 `image_generate`，凭据和服务选择继续由 Hermes 管理。
- 教师在 Desktop 设置蓝图预算，填写单页估算并授权。可单页或逐页预留，可依次执行已预留任务。
- SQLite 事务先提交任务认领，再调用外部服务。并发、重放和未知结果不会自动重复同一外部请求。
- 默认复用同配置和提示词的成功图片，校验存在性与 SHA-256。排队或执行中重复预留返回原任务。重新生成需另行授权并保留历史。
- 保存生成图原始字节和哈希。非16∶9图片另存等比留边版本，保留原像素、偏移和背景色记录。处理后超出尺寸或文件限制时保留原图并报告比例失败。
- Desktop 提供持久状态、分页、预览、原生高清下载、取消、错误和教师核对。运行中取消需确认可能计费，迟到结果只保留历史。
- 视觉检查独立识别实际可见文字及原生元素布局，再与蓝图标题和正文逐字比对。提取时不提供预期文字，避免识别器代替教师校正错字。
- 视觉调用复用图片预算、费用与任务认领。结果保留图片哈希和完整布局，供 Phase 5 重建复用。
- 教师审核使用乐观版本控制。退回图片不进入新任务缓存，损坏文件拒绝下载。
- schema 5–7 逐级迁移，已有课程、文档及审核数据继续保留。

## 费用与结果口径

费用使用整数 micro-USD。调用前预留教师估算，服务报告金额存在时更新，缺失时沿用估算。账目用于任务费用记录，服务商实际账单仍可能高于估算。

自动文字匹配保留视觉模型误读的可能性。教材准确性、图解关系、主题一致性与投影可读性仍由教师核对。识别布局已接入持久任务，完整多页可编辑 PPTX、复杂图片区域、渲染差异与自动修复继续在 Phase 5 实施。

## 验证记录

Python 使用官方 `scripts/run_tests.sh`。图片行为测试使用真实图像文件和模拟服务响应，覆盖预算、认领、缓存、费用、取消、配置变化、比例规范化、像素保留、审核版本、损坏文件、视觉提取和文字差异。

Desktop 使用实际 Electron、Gateway、Agent、Skill、SQLite 与原生文件传输。模型服务位于本机，生图提供者为仅安装到隔离测试配置的固定图片提供者。结果只验证技术流程。固定图片的文字与测试蓝图存在差异，视觉检查应显示未匹配项。

首次视觉界面测试发现测试服务漏接辅助请求，已修正辅助路由。限定原生会话工具集后，测试模型改为直接调用 `skill_view`，并断言加载结果成功。

最终通过数量和日志入口更新在 `TEST_RESULTS.md`。外部证据目录为 `E:\TeacherAgentData\phase4-evidence`。真实付费模型生成与自动还原质量尚待服务配置及费用授权。
