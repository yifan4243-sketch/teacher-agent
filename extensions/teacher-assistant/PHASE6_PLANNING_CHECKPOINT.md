# Phase 6：学期日期与章节课时分配检查点

本次实现学期计划的第一个可运行模块，包括原生Agent工具、真实数据库与中文Desktop。Phase 6的日历发布、调课、进度、后台提醒及DOCX/XLSX/PDF导出继续实施，未将整个阶段标记完成。

## 实现

- schema 13保存计划版本、所用教材版本、课程时间快照和配置；每次实际课次独立入表并关联计划及真实章节ID。
- 依据输入的学期起止日期、多个每周授课时段和停课日期生成日期，支持最长370天。界面不预填上午样例时间。
- 根据教材目录或教师明确选取的章节分配课次。每章至少一次，其余课次按1–10难度权重及最大余数法分配，余数相同时按教材顺序决定，保证总课次数量一致。
- 父章节与子章节不能同时作为独立分配单元；课次不足时明确要求调整。重复时段、时段重叠、跨午夜及跨课程教材关联均拦截。
- 复习、综合练习、考核课次可单独预留，当前依次放在教学章节之后。考核时长独立配置，不套用两节教学时间。
- 课程快照区分实际教学、总休息和日历跨度；常规课次保留40教学＋10休息＋40教学三个时段，同一个课次ID。
- 当前日期时间口径明确为北京时间Asia/Shanghai。月度按自然月、每周按ISO周分组，均引用真实课次ID。
- 原生teacher_records支持plan.save/get/list，Skill说明实际日期、来源和版本语义。Desktop支持课程/教材选择、多个每周时段、停课日期、章节权重、周/月查看及重算保留旧版本。
- 所有数字由确定性程序计算；本模块不调用模型，也不会自动发布日历或启用提醒。

## 验证

完整教师回归12文件52项通过。新增2项行为测试覆盖实际日期和停课、章节权重2:3分配、40＋10＋40、独立120分钟考核、周/月汇总、重放、版本保护、来源和冲突拦截。旧schema迁移测试改为构造真实schema 10并复制既有数据，避免以后新增表影响旧版本升级证明；关联与失败回滚继续通过。

真实Electron/Gateway/SQLite通过教师界面填写虚构测试配置：2026-11-02至11-30，每周一08:20和周三14:00，11月11日停课，另有一次练习、复习和120分钟考核。实际计算8课次、教学560分钟、日历750分钟、考核120分钟。去掉停课日重算v2为9课次、教学640分钟、日历840分钟，v1仍可切回。周范围2条课次、月范围8条课次与数据库一致。

上述日期为明确测试数据，不是用户真实校历。此前文档/图片相关测试模型仍为本机模拟服务；本计划计算链路模型调用数为0。证据见 `phase6-evidence/planning`。

TypeScript、原生插件校验与仓库15项检查通过。React检查清单复核了查询依赖、版本切换的表单重建、受控每周时段和输入标签，没有加入额外UI依赖。

首次定向运行发现日期对象不能直接进入旧写请求指纹编码，已改为Pydantic的JSON模式规范化后再计算指纹；既有操作的完整回归继续通过。原始失败日志和修复后成功结果分别保留。
