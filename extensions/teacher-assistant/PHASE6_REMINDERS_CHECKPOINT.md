# Phase 6 提醒与待办

## 已实现

- schema 16保存提醒设置、教师待办及每次通知尝试，数据按Hermes Profile隔离。
- 待办支持作业、考试、备课和个人事务，可关联课程、调整截止时间、完成或取消，使用版本校验及审计记录。
- 从当前已发布的实际课表计算课前、备课与考试提醒。调课、停课及完成待办后取消原有排队记录。备课提醒显示授课稿、教案的审核准备情况及课次关联情况。
- 时间统一使用北京时间。三种课表提前时间可分别关闭，待办单独配置提前分钟，超过补发窗口的提醒保留过期记录。
- 发送前持久认领，重复与并发触发由数据库协调。失败或中断的发送由教师显式重试，追加尝试记录并保留原结果。结果未知时保持发送中断记录。
- Windows通知使用当前用户的WinRT Toast接口，每个Profile具有独立应用标识。通过JSON传递正文并以XML文本节点构造通知，保留系统接受回执及通知历史核对结果。
- Windows任务计划程序以当前用户的交互登录令牌、普通权限运行，每分钟调用Hermes原生定时器。原生任务使用`no_agent`脚本，无需模型。宿主环境采用现有`activate.ps1`使用的包管理激活命令。
- 后台安装、修复和停用通过教师界面执行。重试注册复用原有任务，升级脚本更新同一个原生任务，保留被修改的本地脚本。插件关闭或提醒关闭后，后续检查尊重该设置。
- Desktop新增提醒设置、待办创建和编辑、状态筛选、分页、提醒记录、显式重试、后台状态及本机通知测试。生产代码使用公开插件接口和原生命令，插件验证通过且没有私有核心导入提示。

## 运行条件

后台依赖有效Hermes运行环境、当前用户登录、Windows任务计划程序和通知接口。机器关机或退出登录期间暂停，恢复后的发送受配置的补发窗口限制。安装路径或运行环境变化后可在工作台点击修复后台。

`accepted`记录表示Windows接口接受通知。专注模式和系统通知显示设置仍由Windows控制，当前没有用户阅读回执。发送中途终止的记录可由教师检查后重试。
