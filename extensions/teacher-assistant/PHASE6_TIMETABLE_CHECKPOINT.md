# Phase 6：计划发布、实际课表、调课与进度

本次将已计算的计划发布为实际课表，加入跨课程冲突检查、日/周/月日历、调课及教师授课进度。后台提醒和计划文件导出继续实施，未将Phase 6或完整专业版标记完成。

## 数据与行为

- schema 14保存发布批次、原始计划课次、实际课表事件及版本间成员关系。教师确认日期和课时并填写审核说明后才能发布；Agent只读实际课表。
- 发布在同一事务中检查全部课次及其他课程的已发布时间。冲突时整次发布撤销，不保留半套课表。
- 同一计划重复发布复用既有批次。替换同一学期需要明确给出当前发布ID，防止过时界面替换新数据。
- 新计划依据原计划的开始/结束、种类及章节匹配旧事件，保留对应的调课、取消和完成记录。已修改的旧事件无法对应新计划时拦截，要求先核对计划，原记录继续保留。
- 旧批次归档时保存事件和进度快照，后续更正不会改写旧快照。事件同时保留原始课次编号及当前计划编号。
- 调课仅修改实际课表，在保持时长及教学/休息分段的前提下整体移动。原计划版本不变，调课与跨课程重叠会被拦截。
- 教师可记录待授课、完成或取消，并填写说明、实际分钟和相同课程/教材版本的备课课次。完成状态由教师填写，不因日期过去自动推断；未来课次不能登记完成。
- 实际分钟不得超过该课次安排的教学/考核分钟。实际教学、考核、剩余教学、逾期未登记及与已完成课次原计划的分钟偏差均由确定性程序计算。
- 每次修改同时校验发布ID和事件版本；恢复或补记被取消课次时重新检查冲突。修改前后、原因、操作者与时间进入审计。
- 中文Desktop支持日/周/月日历、课程筛选、课次展开、调课、授课记录、备课关联与修改历史。常规大课合并为一个事件，课间不作为独立课程。
