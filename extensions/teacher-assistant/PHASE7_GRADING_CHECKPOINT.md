# Phase 7 答卷评分与正式成绩模块

## 实际实现

schema 20新增答卷版本、评分草稿、正式成绩版本、错题记录和原生辅助批改任务。学生答卷关联已审核试卷中的确定题目版本。录入、更正、评分和正式发布前校验课程、班级、学生及选课关联，归档记录会阻止建立新的评分关联。

答卷逐一记录各题作答，保留原始文字中的空白。更正另存版本。客观题采用本地确定性评分，单选和多选核对正确选项集合，判断题核对布尔答案。填空题按NFKC、大小写折叠和空白规范化匹配已保存的接受答案，整数分值按空位顺序均分，余数依次分配。

评分草稿保存自动得分、主观题建议、Rubric逐项得分、评分意见及模型置信度。主观题得分需等于评分要点合计，每项处于对应上限内。界面将低于80%的模型置信度标为重点人工核查。教师可以逐项调整，调整客观题自动分值时需填写该题复核原因。

教师勾选答案发送授权后，通过已有grading阶段模型及Hermes原生会话启动辅助批改。teacher-grading Skill读取确定题目版本、学生主观答案、参考答案及Rubric，再保存建议。答案读取和建议保存绑定该任务的原生runtime session，其他会话会被拒绝。本地学生姓名、学号和班级用于身份关联，模型上下文包含已授权的主观题答文与评分标准。

正式发布需要教师核对全部评分、填写复核说明并确认。发布事务同步保存正式成绩与错题。更正发布关联前次成绩，当前记录保持唯一，旧成绩和旧错题继续保存。并发发布、旧答卷和旧评分草稿受到版本校验。已发布草稿在界面显示发布状态，更正通过新评分草稿进行。

Desktop提供答卷录入、更正、计算自动分、启动辅助批改、低置信度提示、Rubric编辑、教师发布、正式成绩和历史成绩查看。生成任务与实际Agent会话持久保存。取消任务阻止后续建议保存，停止模型请求使用原生会话的停止按钮。

## 验证与修复

教师插件完整回归18文件77项通过，关闭文件自动重试。评分定向用例覆盖精确与部分填空分值、答卷版本、学生关联、评分边界、未经同意的模型调用、跨原生会话访问、低置信度建议、教师发布、并发更新、成绩与错题历史、旧稿及取消后的保存。

真实Electron、Gateway、原生Agent及SQLite界面验证中，本机模型服务给出4分主观题建议及40%置信度。教师逐项核对后将该题评为4.50分，合计9.50分并生成0.50分错题记录。随后教师创建新评分草稿，更正为10分。数据库保留950和1000两个整数总分，当前成绩唯一，旧错题记录及教师说明均存在。刷新后仍可查询。

初次并行全回归72项通过，出现5个插件加载阶段错误，均为原生10秒导入超时。教师插件的操作注册改为保存固定schema和handler路径，实际调用时导入对应业务模块。原生工具列表和权限分派继续沿用既有接口。随后回归发现一个失败注入测试依赖service模块的内部workflows导入别名，已改为导入实际执行的同配置workflows模块。最终77项通过。

界面测试扩展时曾在完成评分后直接操作已离开的命题页，造成测试导航超时。已补齐实际页面导航，命题、评分、成绩更正和刷新链路重测通过。后续最终界面回归及检查日志保存在本模块证据目录。

schema 19非空试卷测试副本升级到20后，课程、题目、命题方案、两份试卷版本、题序关联、生成任务和四份导出记录的全部哈希保持一致，外键校验通过。源数据库以只读方式打开。

最终原生Desktop两项完整回归通过，评分补充定向5项再次通过，包含答案空白保留、布尔置信度拒绝及已发布草稿状态。TypeScript、插件验证与仓库15项检查通过。所有学生及答卷为虚构测试资料，模型通过本机脚本服务响应，本轮外部付费模型调用0次。真实模型评分质量仍待授权联调。
