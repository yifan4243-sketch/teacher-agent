# Phase 7 批改报告导出

## 实际实现

schema 21新增批改报告导出记录。教师可以从正式成绩和历史成绩详情下载DOCX或PDF报告。报告关联确定的成绩、答卷、评分草稿、试卷和题目版本，包含学生姓名、学号、答卷班级、课程、教材版本、教师复核时间、总分、逐题得失分、学生作答、参考答案、解析、Rubric逐项得分、评分意见和教材定位。

报告使用导出时的姓名及学号，答卷班级按提交记录关联。姓名等报告内容变化会产生新的内容哈希、导出记录和建议文件名，已有文件保留。成绩更正后的当前报告与历史报告分别关联各自成绩，缓存依据内容哈希与格式查询。已归档学生的历史成绩仍可导出。

报告复用既有中文A4 DOCX/PDF生成器。成绩和原始答卷数据通过本地教师RPC读取，教师审核发布后的成绩用于正式报告。文件下载复用配置档案归属和SHA-256校验。

## 测试与修复

完整教师回归19文件80项通过，关闭文件自动重试。批改报告、试卷和计划导出的定向9项通过，最终报告定向3项再次通过。测试覆盖实际DOCX/PDF内容、身份更正后的新文件、历史与归档记录、Agent访问限制、文件损坏、失败回滚和稳定请求ID重试。

真实Desktop、Gateway、原生Agent和SQLite完成教师评分、成绩更正、当前及历史报告下载。9.50分历史成绩和10分当前成绩分别导出DOCX/PDF，共4份批改报告。重读文件核对姓名、学号、复核说明、北京时间和总分。实际DOCX通过本机WPS导出PDF，与直接生成的PDF分别渲染并逐页检查。

文件失败测试在fsync边界注入错误，复现了已有store_bytes实现残留暂存文件的问题。已将写入、刷新、同步和文件发布一起纳入清理范围。修复后暂存文件得到清理，导出数据库事务回滚，正式成绩保留，同一请求ID可重新成功执行。计划、试卷和报告共用文件校验逻辑。

schema 20非空评分数据库副本升级到21后，答卷、3份评分草稿、2份正式成绩、错题和原生批改任务的全部记录哈希保持一致，外键校验通过。源数据库以只读方式打开。

TypeScript、插件验证与仓库15项检查通过。测试全部使用虚构学生资料，原生Agent响应来自本机模拟模型。报告生成、身份缓存和文件一致性检查通过真实实现执行，本轮外部付费模型调用0次。
