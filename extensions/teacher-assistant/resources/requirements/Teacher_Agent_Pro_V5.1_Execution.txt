## 三、开发模式：一次授权，连续实施

这是本轮最重要的工作方式要求。

### 3.1 连续执行

从 Phase 1 开始，依次开发至 Phase 9。

每完成一个阶段：

1. 自动运行测试。
2. 分析失败原因。
3. 修复代码。
4. 执行回归测试。
5. 更新开发记录。
6. 创建 Git Commit。
7. 在安全且有推送权限的情况下同步开发分支。
8. 自动进入下一阶段。

**不要在阶段之间暂停等待我输入“继续”。**

### 3.2 自主解决普通技术问题

遇到以下问题时，应自行调查并解决：

- 代码错误。
- 依赖冲突。
- Windows 路径问题。
- 测试失败。
- 数据库迁移问题。
- Hermes Plugin 加载问题。
- API 类型不匹配。
- 前端构建失败。
- 文档排版问题。
- PPTX 结构问题。
- Git 普通提交问题。

不要把每一个技术决策都交还给用户。

需要选型时，优先参考已经批准的架构，并采用低成本、稳定、可维护的方案。

### 3.3 需要用户授权的例外

仅在涉及以下情况时才暂停请求授权：

- 需要使用尚未授权的付费模型或付费 API。

- 需要系统管理员权限或改变系统级安全设置。
- 需要对外发送真实学生个人信息。
- 需要进行不可逆或具有重大风险的操作。

不得为了避免询问而绕过权限。

### Phase 2：教材知识库

交付：

必须能够从教材内容中准确检索知识点，并保留可验证来源。

### Phase 3：授课逐字稿与正式教案

交付：

- 教师授课逐字稿生成 Skill。
- 参考范例的课堂语言风格。

- 教师动作和课堂互动。

- Word 教案模板自动填充。
- 教案审核和版本管理。
- DOCX 导出与排版检查。

**授课逐字稿和正式教案只允许导出 DOCX。**

教案必须使用仓库中保存的原始 Word 模板。

时间规则：

- 第一小节 40 分钟。
- 课间休息 10 分钟。
- 第二小节 40 分钟。
- 日历跨度 90 分钟。
- 实际教学 80 分钟。

不能将课间休息计入实际讲授时间。

- Slide Blueprint。
- 授课稿与 PPT 页面关联。

- 参考图上传。
- 单页重新生成。
- 设计图预览。
- 图片内容准确性检查。
- 生成成本记录。

必须保证 PPT 页面内容与教材和授课稿对应。

### Phase 5：图片转可编辑 PPTX

交付：

- 图片布局解析。

- 页面预览。
- PPTX 渲染。
- 视觉差异检查。
- 自动布局修复。
- 单页修改。
- 完整 PPTX 导出。

优先使用已经批准的 Image-to-Code 设计方案。

不允许未经许可证授权复制专有 Codex Skill。

可以自主开发 Hermes 专用的图片转 PPTX Skill。

**不能将整张设计图作为幻灯片背景，冒充可编辑 PPT。**

同时保留结构化模板生成模式作为备选。

此模块技术风险最高，应尽早运行真实样例验证，不要拖到系统全部开发完成后才测试。
